Tablet build

A separate, standalone variant for ARCore Android tablets — no glasses and no Beam Pro involved. Everything runs on the tablet itself.

Joan Tablet — ARCore variant

Runs the show on a tablet screen as a “magic window”: move the device to look around the scene. Includes an on-screen Passthrough toggle that composites the rear-camera feed behind the content — the tablet's version of the glasses' see-through — while keeping the VFX particles.

In Drive, download joan-tablet.apk.

⬇ Get from Drive
📱

The tablet build needs ARCore. It requires an ARCore-certified device (Galaxy Tab S9 verified) with Google Play Services for AR installed — which needs a Google account signed in on the tablet, since it installs through the Play Store. Without it, the app falls back to gyro-only 3DoF (rotate to look, no walking) and passthrough is unavailable.

📦

The APKs are ~394 MB each, so they are hosted on Google Drive rather than in this repository — GitHub caps files at 100 MB, and this documentation repo is public. Access is managed through the Drive folder.

Builds · Installing

Installing a build

The device needs Developer Mode and USB debugging on first — see Glasses Setup → Setting up from scratch.

Download the APK

Grab the file from the Drive links above, onto the computer you'll sideload from.

Connect the device

Plug the Beam Pro into the computer using its data USB-C port (the other one is power-only and is invisible to adb). Confirm it appears:

adb devices

Install

Sideload the APK. -r updates in place if that build is already present:

adb install -r joan-7-24.apk

Launch it

Glasses builds: plug in the glasses, wait for stereo, then start the app from the Glasses Control app — each build appears separately by name.

Tablet build: just open it from the app drawer. No glasses, no host device, nothing else to connect.

🧭

Telling them apart on-device: the glasses builds show as “joan-of-the-city” (main) and “Joan LS-Shadow”. Because every build has its own package ID, installing one never overwrites another — they coexist.

⚠️

The build must include the XREAL plugin. A build made without the XREAL loader enabled installs and opens, but has no head tracking and won't appear in Glasses Control. Both builds above have it enabled.

Builds · Notes

Notes & known issues

Stray cameras can black out the view

If a build shows nothing in the glasses, check for extra enabled cameras at depth 0 in the scene. The XR camera renders at depth −1, so any screen-rendering camera at depth 0 clears the frame on top of it and wipes out the content. This is what made the first LS-Shadow build appear empty; disabling those cameras fixed it.

The scene starts empty by design

Nearly all content — including all of the VFX particle effects — is cue-gated and inactive at startup. An empty view before any cue fires is expected, not a broken build. Fire cues from the controller to bring content in.

Package IDs vary between builds

Team builds normally use com.joanofthecity.tester. The two builds above were given distinct IDs specifically so they can coexist on one device. If you're checking what's installed, confirm with aapt2 dump packagename <apk> rather than assuming.
